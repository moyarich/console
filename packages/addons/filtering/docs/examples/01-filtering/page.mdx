The filtering addon contributes a structured-message predicate while keeping filter state outside the source message collection.

Use the method toggles, text field, and source selector together. The example also keeps a host-owned `filter` predicate active, so addon criteria compose with existing application filtering instead of replacing it.

<RunnableExample source={source} sourcePath="example.tsx" />

## Configure filtering

See the [API reference](#/addons/filtering/reference/filtering) for the contract and options.

```tsx
import { Console } from "@moyarich/console";
import { createConsoleFilteringAddon } from "@moyarich/console-addon-filtering";

const filteringAddon = createConsoleFilteringAddon();

<Console messages={messages} addons={[filteringAddon]} />;
```

## Combine host and addon filters

See the [API reference](#/addons/filtering/reference/filtering) for the contract and options.

```tsx
<Console
  messages={messages}
  addons={[filteringAddon]}
  filter={(message) => message.source !== "internal"}
/>
```

# Application-owned processor pipeline

Use the `processors` prop to control the order directly from your React application. The runnable example lets you append task events, reset the sample, and clear the current output.

## What the processors do

1. `worker-prefix` removes the visible `[worker]` prefix and adds `metadata.runtime = "worker"`.
2. `task-event` reads the **transformed** ANSI-stripped text and accumulated runtime metadata, then promotes recognized `TASK START` and `TASK DONE` lines into structured values.

This ordering is intentional: reversing these processors means the task parser sees the unnormalized prefix and misses the task event. `metadata` is available to later processors and resolved-output consumers but does **not** create a visible label on its own.

## Behavior and APIs

Each processor receives `output`, ANSI-stripped `text`, `entry`, `index`, `id` and `stream`. A returned patch can replace `data`, add `metadata`, set `structuredValue`, or provide `links`. An exception in one processor does not block later processors. Replacing `data` invalidates link ranges created for earlier text.

For non-React use, call `processConsoleOutputEntry(entry, index, processors)`. For raw controls, line normalization, processors, and `controlEvents` in one pipeline, use `resolveConsoleProcessOutput(entries, processors, controlParsers)`. To retrieve entry/output pairs only, use `resolveConsoleProcessOutputEntries`.

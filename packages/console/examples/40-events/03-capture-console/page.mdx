### Capture the global console from React

See [Capture the global console](#/package-console/events/capture-console).

With `passThrough: true`, calls are both captured and forwarded to the original console, so they still appear in browser DevTools.

To capture a different existing `Console` object, provide `consoleTarget`:

See [Capture a custom console](#/package-console/events/capture-console).

### Capture outside React

Use `captureConsole()` when you want capture without the state hook.

See [Capture outside React](#/package-console/events/capture-console).

The returned function restores the original console methods.

## Capture a custom console

```tsx
const { messages, clear } = useConsoleMessages({
  capture: true,
  consoleTarget: iframe.contentWindow.console,
  source: "iframe",
});
```

## Capture the global console

```tsx
const { messages, clear } = useConsoleMessages({
  capture: true,
  source: "current-page",
  passThrough: true,
});

<Console messages={messages} onClear={clear} />;
```

## Capture outside React

```ts
const events = createConsoleEventEmitter();

const restore = captureConsole({
  events,
  consoleTarget: previewConsole,
  source: "preview",
  passThrough: true,
});

// later
restore();
```

## Bounded history and discarded messages

`useConsoleMessages({ maxMessages: 1000 })` retains the newest messages and reports `droppedCount` when older entries are discarded. `retainedCount` is derived directly from `messages.length`. Initial messages and direct `setMessages` replacements obey the same retention limit. `clear()` and changes to `resetKey` reset both history and the dropped counter.

```tsx
const { messages, droppedCount, retainedCount, clear } = useConsoleMessages({
  maxMessages: 1000,
});

return <>
  {droppedCount > 0 && <p role="status">{droppedCount} older messages discarded</p>}
  <Console messages={messages} onClear={clear} />
  <small>{retainedCount} messages retained</small>
</>;
```

Session snapshots and exports only include the messages still retained. If dropped-history accounting should appear in an exported report or restored session, persist `droppedCount` separately as application metadata; dropped messages cannot be recovered from the current history.
